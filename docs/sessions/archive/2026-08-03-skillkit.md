### 1.2 结构性事实

- **CLI project remove 是薄壳**（本次核心）：调 core `Project::remove(paths, id)`（上轮已实现 + 测试），CLI 只加 clap 变体 + `run_remove` helper。core/server/CLI 三端现在都有注销入口。
- **`run_remove` 抽成独立 helper**（对齐 `skill.rs::run_remove`）：因 clippy `too_many_lines` 阈值 100——`project.rs::run` 是 10 分支 match 分发器，加 remove 后 114 行超限。抽 helper 既减行又对齐 skill 模式，不顺手重构其他分支（最小改动）。
- **确认模式对齐 skill remove**（`skill.rs:111`）：默认 stdin 读 `y/n`，`--yes` 跳过。project remove **不加 `--json`**（remove 无数据可输出，对齐 Rebind；skill remove 的 --json 是因要返回 `{id, removed_canonical}`）。
- 默认多 agent + scan_shared 认 `.agents/skills` 共享池（上轮）——不变。
- 其余不变量（agent 能力配置驱动、canonical 池子 `~/.skillkit/.agents/skills/`、computed_hash 版本、双目录职责、跨实体 id 引用）详见 archive `2026-08-02-skillkit.md` §1.2/§3.2 + spec §7。

## 3. 关键背景

### 3.1 CLI 危险操作确认模式（改 CLI remove/uninstall 类命令必读）

- skill remove（`skill.rs:111` `run_remove`）确立的模式：默认 stdin 读 `y/n`，`--yes` 跳过，`--json` 隐含跳过且输出结构化结果。
- project remove（`project.rs` `run_remove`）对齐：默认 `y/n`，`--yes` 跳过；**不加 `--json`**（remove 无数据可输出，Rebind 也没加；skill remove 的 --json 是为返回 `{id, removed_canonical}`）。
- `ProjectNotFound`（`core/src/error.rs:41`）错误含引导：「project 不存在：{id}（先 `skillkit project add <path>` 注册）」，CLI `?` 传播即可，符合「反馈引导行动」。
- `clippy::too_many_lines` 阈值 100：`project.rs::run` 是多分支 match 分发器，再加分支会超限——新分支抽 helper 函数（不要内联，不要 `#[allow]` 压制）。
