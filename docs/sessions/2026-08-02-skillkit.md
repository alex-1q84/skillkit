## 3. 关键背景

### 3.1 profile 绑定驱动（本次核心，改 Projects 时必读）

- `Project` 字段：`applied_profiles: Vec<String>`（绑定的 profile 名）+ `installed_skills: Vec<String>`（apply 唯一依据，由 applied_profiles 推导）。`set_profiles(names, profiles)` 替换语义：设 `applied_profiles = names`，重算 `installed_skills` = 所选 profiles 的 skills 并集（去重保序）。
- 「应用」数据流：`POST profiles` → load 所选 profiles（任一不存在给可读 err，不 500）→ `set_profiles` → save → `run_apply(false)` 落地 → 再 save（locked_shas 更新）→ 返回工作台页（report: Some）。
- global skill 绑定后进 `installed_skills`，但 `compute_diff` 只对 local scope 生成 expected、apply 时 global 走 `ensure_global_claude`（不 per-project 落地），详情页 local 区块按 scope 过滤不展示。
- **GUI 替换 vs CLI 追加语义差异**：GUI 绑 profile 是全量替换 `installed_skills`；CLI `project apply <profile>`（`crates/core/src/project.rs::apply_profile`）仍是追加语义。两者面向不同场景（GUI 重设绑定 / CLI 增量补绑），暂不统一。

### 3.2 htmx 写操作模式（改 GUI 时遵守）

- 写操作（POST/DELETE）一律完整页 body outerHTML；GET（find/scan/browse）返回局部片段。片段外层固定 id（`status-panel`/`browse-panel-*`），htmx 替换后 id 不丢。
- 重复 key 表单（`profiles=a&profiles=b`）用 `form_urlencoded::parse(&body).filter(...)` 手动收集（serde_urlencoded 不支持重复 key→Vec）。
- handler 预计算展示数据（`ProfileCard`/`ProjectRow`/`local_skills`），避免模板调方法（askama「方法借用参数」坑，如 `contains(&x)` 编译失败）。
- askama `{% if let Some(r) = report.as_ref() %}` 用 `as_ref()` 明确借用避 move；`{% for p in &profiles %}` 借用迭代。
- 13 条 htmx/askama 坑（match 头花括号歧义、include 不传变量、`%2F` 编码、尾斜杠 404 等）详见 archive §8.2。

### 3.3 npx skills 行为 + M0/M1 不变量

详见 archive §3.1/§3.2。要点：下载委托 `npx skills add`（canonical 池子 `~/.skillkit/.agents/skills/`）；`computed_hash` 源自 skills-lock.json；apply 闭环 `compute_diff`→`land_one`→`run_apply`→`build_status`，agent_dir 映射 `claude-code`→`.claude`；`npx skills update` 对 local source 静默 no-op（已知限制）。
