### 1.2 结构性事实（架构层）

- **三层共享 core**：core 全部业务逻辑，cli/server 薄壳。无常驻 daemon，文件锁（`~/.skillkit/.lock`）串行化并发写。
- **单版本模型**：canonical 物理存储只有一份（`~/.skillkit/.agents/skills/<source>/<skill>/`），版本/hash 记在 registry。多版本不分目录（YAGNI）。
- **skill 双 scope**：global（全局基座，`~/.agents/skills/` symlink 落地，独立）vs local（场景/项目组合成员）。**互斥**：global 不属任何 profile、不进任何 project.installed_skills（决策 17，core 硬约束）。
- **agent 能力配置驱动**：是否 symlink、是否直读池子声明在 `config.toml`；`Config::default()` 默认 claude-code/cursor/codex 三大主流。
- **项目 agents 精确探测（决策 19，本次重点之一）**：注册/绑定/同步时按项目根目录探测——配置目录（`.claude`/`.codex`/`.cursor`/`.agents`）命中即按目录判定（多则全收），无配置目录按指令文件（`CLAUDE.md`→claude-code、`AGENTS.md`→开源标准），全未命中回退开源标准 `.agents/`（copy 落地）。探测逻辑收敛在 `crates/core/src/detect.rs`。
- **项目级 `.agents/skills/` 双角色**：shared 真实目录只读发现（归属 `agents/<name>`）；探测未命中具体 agent 时兼作开源标准 local 落地目录（参与 apply）。
- **项目 local skill 平铺落地**：`<agent>/skills/<skill>/`，不建 `local/` 子目录（Claude Code 只发现一层）；git 忽略写 `<project>/.git/info/exclude`。
- **约束红线**：`~/.agents/skills/` 只放全局公共 skill，绝不写元数据文件；元数据全收 `~/.skillkit/`；不管 Claude 原生插件和 `~/.claude/commands/`。

### 1.3 GUI 关键交互面

## 3. 关键背景

### 3.1 scope 互斥 + 转移模型（改 Skills/Profile 必读）

global skill 是全局基座，不属 profile/project；local 才进组合。转移=改 scope + 立即同步物理落地 + 清引用。core 用 `&Registry` 校验 scope（scope 只存 registry）。详见决策 17/18。

### 3.2 agent 探测优先级与回退

探测表固定（claude/codex/cursor/agents）。配置目录优先于指令文件；多配置目录全收；全未命中回退 `.agents/`（开源标准，copy 落地）。新主流 agent 出现，在 `detect.rs` 表里加一行即可。`scan_shared` 在 `proj.agents` 各 agent 目录之外，只读发现项目级 `.agents/skills/` 共享池。

### 3.3 改 CSS/模板生效链路（高频踩坑）

改 `app.css`/Askama 模板 → `cargo build -p skillkit-cli`（rust-embed 重新打包）→ `pkill -f "target/debug/skillkit serve"` → 重启 serve → 浏览器强刷（token 变了）。不重建二进制只重启 serve，CSS/模板变更不生效。GUI 用 `skillkit serve`（cli 二进制）起，不用 `cargo run -p skillkit-server`（后者无 bin target）。

### 3.4 GUI 调试（playwright）

playwright 装在 `~/.local/pipx/venvs/playwright/bin/python`（非项目依赖）。SSE 长连接致 `wait_until="networkidle"` 永不空闲，必须用 `wait_until="load"`。截图读取偶报「Unsupported Image」，改用 DOM 断言（`getComputedStyle`）验证样式。
