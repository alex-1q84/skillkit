## 1. 当前状态

### 1.1 命令表面

CLI 顶层分组：`source` / `install`(add/**local 新增**) / `skill`(find/list/remove) / `upgrade` / `import-existing` / `project` / `profile` / `rescope` / `serve`。

- **`skillkit install local <目录|zip> [--name N] [--scope global|local] [--force] [--json]`**：把外部 skill 目录或 zip 装入 canonical 池，算 sha256 标记 managed，注册 `local/<name>`（伪 source，不进 SourcesStore）。目录支持根/单层父目录（zip 解出常见）两种布局；zip 防 ZipSlip + 拒 symlink 条目 + 体积/条目上限（防 zip bomb）。

GUI 端点（`/{token}/` 前缀）按页：sources / skills / profiles / projects(workspace) / 详见 §1.3 和各路由文件。token 每次启动随机，从启动日志 grep `[0-9a-f]{32}`。

### 1.2 结构性事实（架构层）

- **三层共享 core**：core 全部业务逻辑，cli/server 薄壳。无常驻 daemon，文件锁（`~/.skillkit/.lock`）串行化并发写。
- **单版本模型**：canonical 物理存储只有一份（`~/.skillkit/.agents/skills/<source>/<skill>/`），版本/hash 记在 registry。多版本不分目录（YAGNI）。
- **skill 双 scope**：global（全局基座，`~/.agents/skills/` symlink 落地，独立）vs local（场景/项目组合成员）。**互斥**：global 不属任何 profile、不进任何 project.installed_skills（决策 17，core 硬约束）。
- **agent 能力配置驱动**：是否 symlink、是否直读池子声明在 `config.toml`；`Config::default()` 默认 claude-code/cursor/codex 三大主流。
- **项目 agents 精确探测（决策 19）**：注册/绑定/同步时按项目根目录探测——配置目录（`.claude`/`.codex`/`.cursor`/`.agents`）命中即按目录判定（多则全收），无配置目录按指令文件（`CLAUDE.md`→claude-code、`AGENTS.md`→开源标准），全未命中回退开源标准 `.agents/`（copy 落地）。探测逻辑收敛在 `crates/core/src/detect.rs`。
- **项目级 `.agents/skills/` 双角色**：shared 真实目录只读发现（归属 `agents/<name>`）；探测未命中具体 agent 时兼作开源标准 local 落地目录（参与 apply）。
- **项目 local skill 平铺落地**：`<agent>/skills/<skill>/`，不建 `local/` 子目录（Claude Code 只发现一层）；git 忽略写 `<project>/.git/info/exclude`。
- **约束红线**：`~/.agents/skills/` 只放全局公共 skill，绝不写元数据文件；元数据全收 `~/.skillkit/`；不管 Claude 原生插件和 `~/.claude/commands/`。

### 1.3 GUI 关键交互面

- **Skills 视图**：7 列表格（id/scope/source/version/hash/归属 profile/ops）；scope 过滤条（global/local/profile，`a.chip` 圆角矩形控件）；行勾选高亮 + 批量归入（assign）/移出（unassign）；scope 转移按钮（`.pill-btn`，→global 绿 / →local 中性）；unmanaged 红色 tag；hash 列 ellipsis + title。**toolbar 新增「安装本地」按钮**（`pill-btn`，hx-get 拉表单片段到 `#install-local-panel`）。样式对齐 `demo/index.html`。

### 2.4 install-local 实现（本次完成，7 任务 TDD）

把 08-07 设计落地，7 个 TDD 任务全部通过，**16 个 core 单元/集成测试 + 2 CLI + 3 server 路由测试**。10 个 commit（`78e6650` → `f4e7dec`）。核心实现：

- **core 新模块 `crates/core/src/install_local.rs`**（`pub fn install_local`，全程持 `"registry"` 锁）：
  - 数据流：zip→tempdir / dir→直接 → `resolve_skill_dir`（根/单子目录/多义报错）→ 读 name（`--name` 覆盖 frontmatter）→ `validate_name`（防逃逸：拒空/`.`/`..`/纯点串/分隔符/非法字符）→ containment 断言兜底。
  - 冲突判定（键=registry id，防跨 source 误删）：`other_owner`（registry 反查 canonical_path 占用）→ `SkillPoolOccupied`；`existing_local` + force 走覆盖；target 存在但无 registry 记录 → 孤儿目录报错（`SkillPoolOccupied(None)`）。
  - 原子就位：复制到 `.staging-{pid}` + hash（rename 前算，缩小失败面）→ force 三段 `target→.old → staging→target → rm .old`（带两段回滚）；非 force 单段 rename。save_raw 失败时回滚物理落地。
  - hash：长度前缀 sha256（`len(path)‖path‖len(content)‖content`，防碰撞），跳 symlink。
  - 安全：`extract_zip` 逐条目 `enclosed_name` + `starts_with(dest)` 双校验 + 拒 symlink 条目（zip 2.4.2 用原生 `is_symlink()`，非 `unix_permissions`）+ 总体积 `MAX_ZIP_BYTES=100MiB` / 条目 `MAX_ZIP_ENTRIES=10000` 上限。
- **`Registry::save_raw`**（`registry.rs`）：不取锁版本，供 install_local 全程持锁调用，避免 `Registry::save` 重取同 key 致**同进程 flock 自死锁**。
- **CLI**：`InstallSub::Local` 变体 + `run_install` 分支（`--json` 输出 SkillMeta，否则人话 `✓ 已安装 <id> → <path>（sha256: <前12位>）`）。
- **server**：`POST /{token}/skills/install-local`（`install_local` handler）+ `GET`（`install_local_form` 拉 `install_local_form.html` 表单片段）+ Skills 页 toolbar「安装本地」按钮挂载点 `#install-local-panel`。
- **依赖**：core 加 `zip = "2"`、`sha2 = "0.10"`、`tempfile = "3"`（tempfile 从 dev-dep 移主 dep，因 install_local lib 代码 zip 分支用 `TempDir`）。

**与计划的偏差**（已闭合，诚实记录）：①zip 2.4.2 读侧无 `unix_permissions()`，改用原生 `is_symlink()`（语义等价）；②tempfile 须进主依赖（计划放 dev-dep 有误）；③计划代码多处触发 clippy `-D warnings`（map_or_else / 嵌套 or-pattern / 显式 match 变体 / too_many_lines），逐项修，含 2 个 `fix(core)` commit；④CLI 测试 `#[derive(serde::Serialize)]` 需补 serde dev-dep。

### 2.5 GUI 走查发现的 2 个 bug（已修）

1. **空 name 表单字段归一**（`d0cdd64`）：HTML 表单空 input 序列化成 `name=`（axum `Form` 反序列化成 `Some("")` 而非 `None`），导致 `install_local` 走 `Some("")` → `validate_name("")` 报「skill 名为空」安装失败（curl 无 name 字段则成功）。修：handler 把空串归一为 `None`（`skills.rs` `name.filter(|s| !s.trim().is_empty())`）+ 回归测试 `skills_install_local_empty_name_field_reads_frontmatter`。
2. **SSE 冲掉写操作 summary 反馈**（`f4e7dec`）：写操作返回完整页含 `<p class="summary">✓…</p>` 反馈，但 SSE `changed`（registry 写入触发 notify）立即发 `GET ?fragment=1` 纯片段刷新，把刚渲染的 summary 冲掉——用户看不到反馈。**既有 bug，影响所有写操作**（rescope/assign/import 都一样），非 install-local 特有。修（layout.html 三处）：①SSE 刷新延迟 300ms（让写操作完整页先落地，避开与 POST 响应竞态）；②summary 展示期跳过刷新（`if (.page-head .summary) return`）；③summary 4s 后自动淡出（避免常驻挡 SSE 同步，对齐 toast 反馈语义）。

## 3. 关键背景

### 3.1 scope 互斥 + 转移模型（改 Skills/Profile 必读）

global skill 是全局基座，不属 profile/project；local 才进组合。转移=改 scope + 立即同步物理落地 + 清引用。core 用 `&Registry` 校验 scope（scope 只存 registry）。详见决策 17/18。

### 3.2 agent 探测优先级与回退

探测表固定（claude/codex/cursor/agents）。配置目录优先于指令文件；多配置目录全收；全未命中回退 `.agents/`（开源标准，copy 落地）。新主流 agent 出现，在 `detect.rs` 表里加一行即可。`scan_shared` 在 `proj.agents` 各 agent 目录之外，只读发现项目级 `.agents/skills/` 共享池。

### 3.3 改 CSS/模板生效链路（高频踩坑）

改 `app.css`/Askama 模板 → `cargo build -p skillkit-cli`（rust-embed 重新打包）→ `pkill -f "target/debug/skillkit serve"` → 重启 serve → 浏览器强刷（token 变了）。不重建二进制只重启 serve，CSS/模板变更不生效。GUI 用 `skillkit serve`（cli 二进制）起，不用 `cargo run -p skillkit-server`（后者无 bin target）。

### 3.4 GUI 调试（playwright）

playwright 装在 `~/.local/pipx/venvs/playwright/bin/python`（非项目依赖）。SSE 长连接致 `wait_until="networkidle"` 永不空闲，必须用 `wait_until="load"`。截图读取偶报「Unsupported Image」，改用 DOM 断言（`getComputedStyle`）验证样式。写操作 htmx 用 AJAX 不触发浏览器导航，**断言别用 `expect_navigation`，改轮询 DOM**（如 `page.locator(".summary", has_text="…").wait_for()`）。

### 3.5 SSE 刷新与写操作反馈的时序（§2.5 修复后必读）

写操作 = 先写状态文件（触发 SSE `changed`）→ 后渲染完整页返回。SSE 若立即刷新会与 POST 响应竞态、冲掉 summary。现链路：SSE 延迟 300ms → 检查 summary 是否在展示 → 在则跳过本次刷新（反馈优先）→ summary 4s 自动淡出 → 恢复 SSE 实时同步。代价：写操作后 4s 内 CLI 侧数据变化不实时同步（单用户本地工具可接受）。
